# 多 agent 界面手测用例

## 先跑自动化

两套自动化已经覆盖了这份文档原本的大部分内容：

```bash
cd codex-vscode
npm test          # = test:e2e + test:ui
```

- `npm run test:e2e` —— 真实 `codex app-server` + 假模型，26 项断言，
  覆盖事件流、订阅、agent 树。详见 `multi-agent-orchestration.md` §5.2。
- `npm run test:ui` —— Playwright 驱动真实构建产物，16 项断言，
  覆盖 tab 路由、状态渲染、布局度量。截图落在 `e2e/webview/screenshots/`。

**先跑这两个。全绿之后，下面的人工部分才有意义。**

自动化已经接管的：单 agent 生命周期、并发不串台、10 个 agent 的 tab 溢出与
主线程 tab 可达性、窄边栏、驱逐后重连与不重复、嵌套 tab 出现与路径、
会话切换不泄漏、降级提示存在性。

---

## 剩下必须人来做的

只有三类：**主观观感**、**跨进程真实链路**、**自动化测不到的交互**。

### 准备

自动化用的是构造好的消息；人工要看的是真实链路。用沙箱，不用真模型——
真模型没法让你按需派 10 个 agent，也没法让某个 agent 挂 3 分钟不动。

```bash
cd codex-vscode
node e2e/ui-sandbox.js        # 保持运行
```

在 VS Code 里打开 `codex-vscode`，按 <kbd>F5</kbd>，选 **Run Extension (mock model)**。
它会先构建，再把 `CODEX_HOME` 指向 `~/.codex-ui-sandbox`，不碰你真实的 `~/.codex`，
不消耗任何额度。在新窗口里打开 Codex 面板。

可用指令：

| 指令 | 效果 |
|---|---|
| `/one` | 派 1 个 agent，约 12 秒完成 |
| `/three` | 同时派 3 个 |
| `/many` | 同时派 10 个（超过订阅上限 8） |
| `/nest` | 派 1 个 agent，它自己再派 1 个 |
| `/slow` | 派 1 个 agent，占 3 分钟不结束 |
| `/exec` | 派 1 个 agent，它去跑 shell 命令 |

---

### M1 观感（自动化只能证明"没坏"，不能证明"好用"）

发 `/many`，然后回答：

- [ ] 10 个 tab 的横向 strip，第一眼觉得拥挤到难用了吗？
- [ ] agent 名字（`worker_1`…）够不够区分？真实场景里名字会更长，会怎样？
- [ ] 要找某个特定 agent，是横拉找，还是应该有别的入口（下拉列表 / 搜索）？
- [ ] 主线程 tab 被钉在最左（sticky），这个处理看起来自然吗？

发 `/nest`，然后：

- [ ] `researcher` 和 `researcher_scraper` 平铺在同一行，不体现父子层级。
      这可接受吗？如果不行，你希望怎么表达层级（缩进 / 分隔符 / 树形侧栏）？

### M2 真实时序（自动化用的是构造消息，看不到真实延迟）

发 `/one`，盯着看：

- [ ] 从发消息到 tab 出现，中间有多久的空白？这段时间界面有反馈吗？
- [ ] agent 完成时圆点变绿，有没有明显滞后？
- [ ] 发 `/many`，10 个 tab 是一次性出现还是逐个蹦出来？后者观感如何？

发 `/many` 等全部跑完，点最前面的 `worker_1`（它必然已被驱逐）：

- [ ] 重连有肉眼可见的卡顿吗？大概多久？
- [ ] 卡顿期间界面显示的是"未订阅，正在重新连接"还是空白？

### M3 中断（涉及真实 turn 生命周期）

发 `/slow`，进 `long_runner` 的 tab，点"中断"：

- [ ] 点击后状态多久变成已中断（红点）？
- [ ] 主线程有没有被一起中断？
- [ ] 中断后再点进该 tab，会不会报错或空白？

### M4 工具调用与文件变更归属

发 `/exec`，进 `builder` 的 tab：

- [ ] 命令和输出显示在 agent 自己的 transcript 里，主线程里没有
- [ ] 如果 agent 改了文件，改动会进主线程的变更列表（数据层已这么做），
      但界面上**看不出它来自哪个 agent**。需要补来源标记吗？

### M5 输入框归属（待定的设计问题）

在某个 agent 的 tab 上，往输入框发一句话：

- [ ] 消息落在主线程，这符合你的预期吗？
- [ ] 发送后视图应该自动跳回主线程吗？**记你的偏好，这是个未决定的设计问题。**

---

## 记录方式

M1 和 M5 要的是偏好，M2–M4 要的是"是/否 + 大致耗时"。
自动化已经保证了正确性，这里要找的是"能用但难用"。

## 收尾

终端里 <kbd>Ctrl</kbd>+<kbd>C</kbd> 停掉沙箱。`~/.codex-ui-sandbox` 下次启动时自动清空。
